# Optional exact completed-stripe reuse

`RISC_CO5300_REUSE_UNCHANGED=1` selects an optional native-only optimization. Default0 preserves existing selection; it changes no hardware/provider ABI or application drawing. The integrator must record the actual native define and source pin. The facade still accepts and processes every row, and the first complete application frame is always transferred before the existing brightness gate opens.

The native bridge attempts one `MALLOC_CAP_SPIRAM|MALLOC_CAP_8BIT` allocation on the first accepted row0 after open. At466×466 this is434,312 bytes, in addition to existing3,728-byte four-row DMA buffer, application/provider framebuffers and optional~927KiB picker cache. Allocation failure is ordinary uncached operation, not failed display startup or an internal-RAM fallback. Allocation is not retried until a later native reopen. The cache is optional performance memory, never DMA storage.

The shadow contains successful physical wire-order pixel bytes indexed by physical row. This handles rotation0/180, even-start noncontiguous partial windows and final short stripes without depending on a fixed logical stripe partition. It is not trusted until a complete sequential application frame has populated every pixel. Exact `memcmp` (not a hash) decides whether a later stripe can omit its SPI window. A changed stripe copies into the shadow only after all SPI command/data completion and CS release succeed. Failed/unknown completion reaches the existing failed-state fence before cache mutation. Rejected rows do not allocate or mutate DMA/shadow. No cache is freed until the preexisting bus/device/pad cleanup has succeeded.

Internal fill invalidates shadow authority before its first command, including a failing fill. Open/close resets all cache state. Brightness alone does not change pixel memory. This optimization assumes the same exclusive panel ownership already required by the native backend; no external writer is silently tolerated.

## Performance recorder

Phase34 remains accepted full-frame elapsed/row count. Phase35 counts only windows that actually issue SPI, but its duration is transferred-window processing: exact comparison, the SPI window and successful shadow copy. It is NOT pure wire or SPI-call time. This keeps the existing two bounded clock samples per processed stripe rather than adding diagnostic callbacks around cache operations. Phase36 value counts processed stripe boundaries, including skipped ones; its duration includes row packing, scheduling and skipped-stripe comparison/processing. Phases37/38 retain maximum transferred-window processing/gap per frame; phase39 remains partial-frame abort. Thus phase34 duration remains phase35+phase36, but their counts need not match. A wholly unchanged frame can have zero transfers and nonzero elapsed/gap time. None of these counters proves visible panel timing.

## Qualification

`tests/test_co5300_reuse.py` reuses exact real-SDK compiler command receipts and compiles the actual native bridge. Four geometry/orientation profiles×2/4/6stripe rows×trace0/1 test full physical panel reconstruction, unchanged and single-changed-stripe frames, final remainder, nonaligned partial windows, initial partial-frame refusal to skip, OOM fallback, fill invalidation, every window failure phase, timeout/unknown completion, rejected row/owner custody, cleanup retries and reopen. The public2-row partial-update behavior remains valid; no change to the earlier4-row composition-only contract is claimed. Normal, ASan/UBSan and target compile receipts are separate. LeakSanitizer is disabled because this executor uses ptrace; explicit owned-allocation cleanup assertions remain.
